# PRD: 할 일 잠금 (Task Lock)

- **Status:** Implemented (Beta)
- **Owner:** Product
- **Last Updated:** 2026-08-16
- **Related:** [현재 제품 스펙](../SPEC.md), [일일 즉시 해제 한도](./daily-unblock-quota.md), [디자인 기준](../../design/unshort.pen)

## 1. 개요

할 일 잠금은 사용자가 직접 지정한 할 일을 완료하기 전까지 Shorts/Reels의 기존 해제 수단을 잠그는 기능이다. 단순히 쇼츠를 참도록 요구하는 대신, 사용자가 먼저 끝내고 싶은 행동을 명시하고 차단 조건으로 연결한다.

미완료 잠금 할 일이 있으면 기존 `그냥 닫기`, `바로 보기`, 30초 뒤집기 타이머 및 광고 충전 UI보다 체크리스트가 우선한다. 사용자가 모든 잠금 할 일을 완료하거나 제한된 미루기를 사용한 뒤에만 기존 차단 흐름으로 돌아갈 수 있다.

완료 판단은 초기에는 사용자 자기 확인을 기본으로 한다. 지원 기기에서는 사진을 서버로 보내지 않고 Gemini Nano로 분석하는 선택형 온디바이스 AI 확인을 제공한다.

## 2. 문제와 가설

### 문제

- 현재 차단은 충동을 잠시 늦추지만, 사용자가 원래 해야 했던 행동과 연결되지는 않는다.
- 30초 마찰을 반복해서 통과하는 사용자에게는 차단 효과가 점차 약해질 수 있다.
- 지나치게 강한 영구 차단은 접근성 서비스나 앱 자체를 꺼버리는 행동을 유발할 수 있다.
- 서버 기반 사진 인증은 민감한 생활 사진을 다루므로 개인정보와 운영 비용 부담이 크다.

### 핵심 가설

> 사용자가 직접 정한 구체적인 할 일을 쇼츠 해제의 선행 조건으로 만들면, 단순한 대기보다 실제 행동 전환율이 높아진다. 완료 판단은 자기 확인을 존중하되, 선택형 온디바이스 사진 확인과 제한된 미루기를 제공하면 강제성과 현실적인 예외 사이의 균형을 만들 수 있다.

## 3. 목표와 비목표

### Goals

- 사용자가 오늘의 할 일을 등록·관리하고 일부 항목을 쇼츠 잠금 조건으로 지정할 수 있다.
- 잠금 할 일이 남아 있으면 체크리스트 오버레이가 모든 기존 해제 수단보다 먼저 나타난다.
- 오버레이와 앱 내부에서 할 일을 완료 처리할 수 있다.
- 광고를 본 사용자는 하루 제한 횟수 안에서 잠금을 30분간 미룰 수 있다.
- 지원 기기에서는 사진과 할 일의 관련성 및 완료 가능성을 온디바이스에서 확인한다.
- 완료, 차단, 미루기 결과를 주간 리포트에서 확인할 수 있다.

### Non-Goals

- AI가 사용자의 행동을 완벽하게 증명하거나 부정 사용을 완전히 차단하는 것
- 사진이나 할 일 데이터를 서버에 업로드하는 것
- 친구, 관리자 또는 제3자의 원격 승인
- 외부 할 일 서비스와의 양방향 동기화
- 포인트, 레벨, 쇼츠 이용권 등 별도의 보상 경제
- 초기 버전에서 여러 날이 필요한 장기 목표를 강제 잠금 조건으로 사용하는 것

## 4. 핵심 용어

| 용어 | 정의 |
|---|---|
| 일반 할 일 | 기록과 완료 체크만 제공하며 쇼츠 차단에 영향을 주지 않는 항목 |
| 잠금 할 일 | 미완료 상태일 때 기존 쇼츠 해제 수단을 잠그는 항목 |
| 할 일 잠금 | 미완료 잠금 할 일이 하나 이상 존재하는 상태 |
| 자기 확인 | 별도 증빙 없이 사용자가 직접 완료 여부를 결정하는 기본 방식 |
| AI 사진 확인 | 촬영한 사진과 할 일의 관련성·완료 가능성을 기기 안에서 분석하는 선택 방식 |
| 미루기 | 할 일을 완료 처리하지 않은 채 할 일 잠금만 일정 시간 유예하는 예외 |

## 5. 사용자 흐름

### 5.1 할 일 등록

```text
할 일 메뉴
  → 할 일 추가
  → 제목 입력
  → 적용일/반복 설정
  → 차단 시작: 지금부터 또는 시작 시각 지정
  → "완료 전까지 쇼츠 잠금" 선택
  → 완료 확인 방식 선택
      ├─ 직접 체크
      ├─ 사진 남기기
      └─ AI 사진 확인(Beta, 지원 기기만)
  → 저장
```

각 항목에 잠금 여부를 개별 지정한다. 모든 할 일을 자동으로 잠금 조건으로 사용하지 않는다. MVP의 잠금 할 일은 당일 완료 가능한 항목을 전제로 한다.

### 5.2 쇼츠 진입

```text
Shorts/Reels 감지
  → 미완료 잠금 할 일 존재?
      ├─ 없음 → 기존 차단 오버레이
      └─ 있음 → 할 일 체크리스트 오버레이
                    ├─ 항목 선택 → 완료 확인
                    ├─ 쇼츠 닫고 할 일로 돌아가기
                    └─ 광고 보고 30분 미루기
```

할 일 잠금 중에는 다음 UI를 표시하지 않는다.

- 기존 30초 뒤집기 타이머 진입
- 바로 보기 및 일일 즉시 해제 한도
- 광고를 통한 즉시 해제 한도 충전
- 프리미엄 즉시 건너뛰기

### 5.3 완료 처리

체크리스트 행을 누르면 바텀시트에서 선택한 할 일을 다시 확인한다. 마지막 할 일을 완료해도 쇼츠를 즉시 열지 않는다.

```text
마지막 잠금 할 일 완료
  → 완료 피드백
  → 기존 차단 정책으로 복귀
      ├─ 30초 생각하기
      └─ 쇼츠 닫기
```

핵심 정책은 `할 일 완료 = 쇼츠 허용`이 아니라 `할 일 완료 = 기존 차단 정책 복귀`이다.

## 6. 할 일 관리 정책

### 6.1 항목 속성

- 제목
- 적용 날짜
- 차단 시작 시각(선택, 디바이스 로컬 시간)
- 반복: 한 번, 매일, 평일, 요일 선택
- 잠금 여부
- 완료 확인 방식
- 완료 상태 및 완료 시각
- 선택 메모
- 선택 사진의 로컬 URI 또는 즉시 폐기 상태

### 6.2 잠금 조건

- 활성 날짜에 해당하는 잠금 할 일을 모두 완료해야 할 일 잠금이 해제된다.
- 시작 시각을 지정한 항목은 해당 시각 전까지 예정 상태로 표시하며 잠금 조건 계산에서 제외한다.
- 일반 할 일은 잠금 조건 계산에서 제외한다.
- 반복 항목은 새 적용일에 새로운 미완료 상태로 시작한다.
- 날짜 변경, 재부팅 및 프로세스 종료 후에도 상태가 복구되어야 한다.
- 앱 시간대는 디바이스 로컬 시간대를 따른다.

### 6.3 수정·취소

- 할 일 편집은 un:short 앱의 할 일 메뉴에서만 제공한다.
- 할 일 행을 누르면 등록과 동일한 바텀시트를 편집 상태로 열어 제목, 잠금 여부, 시작 시각, 반복 및 확인 방식을 변경한다. 완료 체크는 행과 분리된 체크박스로만 수행한다.
- 잠금 중 항목 삭제 또는 잠금 해제에는 기존 충동 방지 패턴과 동일한 확인 마찰을 적용한다.
- 사용자를 복구 불가능한 상태로 두지 않는다. 잠금 취소 경로는 항상 제공하되 즉흥적인 우회가 되지 않도록 기록과 확인 단계를 둔다.
- 장기간 미완료 상태를 방지하기 위해 당일 항목은 다음 적용일 정책에 따라 만료 또는 재생성한다.

## 7. 광고 기반 미루기

### 7.1 기본 정책

| 항목 | 기본값 |
|---|---:|
| 광고 1회당 잠금 유예 | 30분 |
| 일일 미루기 한도 | 2회 |
| 유예 중 추가 미루기 | 불가 |
| 유예 종료 | 실제 시각 기준 자동 복원 |
| 할 일 완료 상태 | 변경 없음 |

운영값은 Remote Config로 조정 가능하게 설계한다.

### 7.2 흐름

```text
할 일 잠금 오버레이
  → "지금 어려워요"
  → 미루기 조건 바텀시트
  → 리워드 광고 완료
  → 남은 횟수 차감
  → 할 일 잠금 30분 유예
  → 기존 30초 차단 정책으로 이동
```

- 광고 실패 또는 중도 종료 시 횟수를 차감하지 않고 잠금을 유지한다.
- 광고는 할 일을 완료 처리하거나 쇼츠를 즉시 허용하지 않는다.
- 유예 중에도 체크리스트는 할 일 메뉴에 남으며 남은 유예 시간을 표시한다.
- 유예 시간이 끝난 상태에서 쇼츠를 보고 있다면 다음 감지 가능한 콘텐츠 전환에서 잠금 오버레이를 표시한다.
- 프리미엄 사용자는 동일한 일일 횟수와 유예 시간을 유지하되 광고 없이 미룰 수 있다. 프리미엄 무제한 미루기는 제공하지 않는다.

## 8. 온디바이스 AI 사진 확인

### 8.1 목적

AI는 할 일 완료의 절대적인 증명자가 아니라 사진이 할 일과 관련 있고 완료를 뒷받침하는지 설명하는 보조 수단이다. 최종 완료 여부는 정책에 따라 사용자가 확인한다.

적합한 예:

- 책상 정리, 설거지 등 결과 상태가 사진에 나타나는 일
- 문제집 풀기, 필사 등 텍스트와 필기를 OCR로 확인할 수 있는 일
- 영수증 정리처럼 대상 물체와 텍스트가 명확한 일

제한적인 예:

- 책 10쪽 읽기, 운동 30분 등 사진 한 장으로 수행량이나 시간을 증명할 수 없는 일
- 복약처럼 오판 시 안전 문제가 생길 수 있는 일

### 8.2 기술 방향

지원 기기에서는 Android AICore의 Gemini Nano를 사용하는 ML Kit GenAI Prompt API에 사진과 할 일 설명을 함께 전달한다. Prompt API는 멀티모달 입력과 구조화된 출력을 사용한다.

예상 출력 모델:

```json
{
  "relevant": true,
  "status": "likely",
  "confidence": 0.76,
  "evidence": ["책상 표면이 비어 있음", "물건이 정돈되어 있음"]
}
```

`status` 값:

- `confirmed`: 사진이 완료를 비교적 명확하게 뒷받침함
- `likely`: 관련성은 높지만 완료를 확정하기 어려움
- `unclear`: 사진 품질 또는 정보 부족으로 판단하기 어려움
- `unrelated`: 할 일과 관련 없는 사진으로 판단됨

LLM 호출 전후에 다음 단계를 조합한다.

1. 사진 밝기·초점 등 기본 품질 확인
2. 필요 시 ML Kit Text Recognition으로 한글 OCR 수행
3. Gemini Nano에 원본 사진, OCR 결과 및 할 일 설명 전달
4. 구조화된 결과 파싱 및 허용값 검증
5. 판정 근거와 다음 행동을 사용자에게 표시

복잡한 다단계 판단을 한 프롬프트에 맡기지 않고 코드로 단계를 연결한다. 결정성 평가에서는 낮은 temperature, 짧은 출력 및 고정된 스키마를 사용한다.

### 8.3 기기 지원과 폴백

- 앱 실행 중 API 지원 상태와 모델 다운로드 상태를 확인한다.
- 지원되는 기기에서만 `AI 사진 확인(Beta)` 옵션을 노출한다.
- 지원되지 않거나 모델을 사용할 수 없으면 `사진 남기기` 또는 `직접 체크`로 폴백한다.
- 추론 쿼터, 배터리 쿼터, 모델 준비 실패 및 백그라운드 실행 제한을 정상적인 제품 상태로 처리한다.
- AI 확인을 사용자가 선택했더라도 기기 상태 때문에 영구적으로 잠기지 않도록 복구 경로를 제공한다.

### 8.4 결과별 UX

| 결과 | 기본 동작 |
|---|---|
| `confirmed` | 근거 표시 후 완료 확인 버튼 제공 |
| `likely` | 애매함을 알리고 사용자 최종 확인 제공 |
| `unclear` | 다른 각도 또는 더 선명한 사진 재촬영 제안 |
| `unrelated` | 관련 사진 재촬영 제안 |
| API 사용 불가 | 자기 확인 또는 일반 사진 기록으로 폴백 |

AI 결과만으로 자동 완료하지 않는다. 초기 Beta에서는 오탐·미탐 데이터를 사진 없이 로컬 집계하고 사용자의 최종 선택과 비교한다.

### 8.5 개인정보

- 사진, 프롬프트, 추론 결과는 서버로 전송하지 않는다.
- 기본값은 분석 후 원본 사진 즉시 폐기이다.
- 사용자가 기록 보관을 명시적으로 선택한 경우에만 앱 전용 로컬 저장소에 사진을 남긴다.
- 분석 화면에 `기기에서만 확인` 상태를 명시한다.
- 분석·광고·Firebase 이벤트를 연결해 사진 내용이나 할 일 원문이 분석 서비스에 전송되지 않도록 한다.

## 9. 리포트

리포트는 생산성 점수나 실패 판정보다 잠금이 실제 행동 전환으로 이어졌는지 보여준다.

### 일간·주간 항목

- 등록한 잠금 할 일 수
- 완료한 잠금 할 일 수와 완료율
- 모든 잠금 할 일을 완료한 날
- 할 일 잠금으로 막은 쇼츠 진입 수
- 미루기 사용 수
- 미룬 뒤 당일 완료한 수와 비율
- 직접 체크·사진·AI 확인 방식별 완료 수
- AI 판정과 사용자 최종 판단이 달랐던 비율

사진 내용, 할 일 원문 및 AI 판정 근거는 Analytics로 전송하지 않는다.

## 10. 우선순위와 기존 정책 충돌

차단 정책 우선순위는 다음과 같다.

```text
1. 할 일 잠금
2. 수면 모드 및 일일 사용 제한
3. 기존 Shorts/Reels 차단 오버레이
4. 즉시 보기 한도 및 프리미엄 지연 제거
```

세부 충돌 규칙:

- 할 일 잠금 중 프리미엄 즉시 건너뛰기는 적용하지 않는다.
- 할 일 잠금 미루기 후에는 수면 모드 등 더 강한 기존 정책이 그대로 적용된다.
- 피드 차단 적용 여부는 초기 범위에서 제외하고 Shorts/Reels에 먼저 적용한다.
- 전체 차단이 비활성화되면 할 일 잠금도 쇼츠 진입을 가로막지 않는다. 할 일과 완료 기록은 유지한다.

## 11. 성공 지표

| 지표 | 정의 | 초기 관찰 목표 |
|---|---|---:|
| 기능 활성화율 | 할 일 잠금을 한 번 이상 설정한 사용자 / DAU | 5~15% |
| 행동 전환율 | 잠금 오버레이 노출 후 당일 할 일 완료 / 노출 사용자 | 30% 이상 |
| 전체 완료율 | 등록된 잠금 할 일 중 완료된 비율 | 50% 이상 |
| 미루기 사용률 | 미루기 사용 / 잠금 오버레이 노출 | 10~30% |
| 미룬 뒤 완료율 | 미루기 후 당일 완료 / 미루기 사용 | 40% 이상 |
| 잠금 취소율 | 잠금 항목 삭제·잠금 해제 / 활성 사용자 | 30% 이하 |
| AI 확인 성공률 | 재촬영 없이 결과를 받은 AI 확인 / AI 확인 시도 | 70% 이상 |
| AI 판단 수용률 | AI 결과와 사용자 최종 판단이 일치한 비율 | 80% 이상 |

강한 잠금 기능이므로 접근성 서비스 비활성화율, 앱 삭제율 및 크래시율을 함께 감시한다.

## 12. 분석 이벤트

이벤트 이름은 구현 시 기존 `AnalyticsEvent` 규칙에 맞춰 확정한다.

- 할 일 생성·완료·취소
- 잠금 설정 활성화·비활성화
- 잠금 오버레이 노출
- 잠금 중 쇼츠 재진입
- 미루기 진입·광고 완료·실패·유예 종료
- AI 확인 선택·지원 불가·모델 준비 실패
- AI 결과 범주와 사용자 최종 선택

이벤트에는 할 일 제목, 사진, OCR 텍스트 및 AI 근거 문장을 포함하지 않는다.

## 13. 단계별 출시

## 14. QA 핵심 시나리오

1. 잠금 할 일이 없으면 기존 차단 흐름이 변하지 않는다.
2. 잠금 할 일이 하나라도 남아 있으면 기존 해제 수단이 표시되지 않는다.
3. 마지막 할 일을 완료하면 쇼츠가 즉시 열리지 않고 기존 차단 화면으로 이동한다.
4. 광고 완료 시에만 미루기 횟수가 차감되고 30분 유예가 시작된다.
5. 재부팅·프로세스 종료·날짜 변경 후 상태가 정책대로 복구된다.
6. 프리미엄도 잠금 할 일을 우회할 수 없고 미루기 횟수는 동일하다.
7. AI 미지원 기기와 모델 다운로드 실패 상태에서 사용자가 잠기지 않는다.
8. 사진과 OCR 텍스트가 네트워크 분석 이벤트에 포함되지 않는다.
9. AI 결과가 잘못되거나 애매할 때 재촬영과 자기 확인 경로가 동작한다.
10. 유예 종료 후 다음 쇼츠 감지에서 할 일 잠금이 복원된다.

## 15. 오픈 이슈

- 잠금 중 항목 삭제에 적용할 정확한 마찰 시간
- 반복 할 일의 자정 초기화와 사용자 지정 시작 시각 지원 여부
- AI 사진 확인을 무료 Beta로 제공할지 프리미엄 기능으로 제공할지
- `unrelated` 결과에서도 자기 확인을 즉시 허용할지 추가 마찰을 둘지
- 동일 사진 재사용 방지를 위한 perceptual hash 도입 여부
- 피드 차단까지 동일한 할 일 잠금을 적용할 시점
